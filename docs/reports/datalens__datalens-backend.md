**1. Проводите изменения через pull request.** Почему важно: По активности решают, живой ли проект: заброшенную зависимость никто не обновит, когда в ней найдут ошибку. Сейчас: Pull request не используются. Что сделать: Вносите изменения через pull request даже в одиночку: история решений и место для проверок CI.

**2. Проверяйте pull request пайплайном.** Почему важно: Без автоматических проверок сломанная сборка и упавшие тесты попадают в основную ветку незамеченными. Сейчас: Пайплайн не срабатывает на pull request. Что сделать: Добавьте в .sourcecraft/ci.yaml триггер pull_request — проверки будут идти до слияния, а не после.
