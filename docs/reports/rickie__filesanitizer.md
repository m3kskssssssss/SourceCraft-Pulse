**1. Настройте CI.** Почему важно: Без автоматических проверок сломанная сборка и упавшие тесты попадают в основную ветку незамеченными. Сейчас: Конфига CI нет. Что сделать: Создайте .sourcecraft/ci.yaml: запуск на push и pull_request, шаги — go vet ./..., go test ./.... Pulse может подготовить этот файл в pull request.

**2. Добавьте .editorconfig.** Почему важно: Код без тестов, линтера и зафиксированных зависимостей дорого менять: ошибки находят пользователи, а не проверки. Сейчас: .editorconfig отсутствует. Что сделать: Положите .editorconfig в корень: кодировка utf-8, перевод строки lf, отступы как в проекте.

**3. Подключите линтер.** Почему важно: Код без тестов, линтера и зафиксированных зависимостей дорого менять: ошибки находят пользователи, а не проверки. Сейчас: Конфиг линтера не найден. Что сделать: Настройте golangci-lint с файлом .golangci.yml. Сначала включите рекомендуемый набор правил и исправьте найденное, потом добавьте запуск в CI.

**4. Проводите изменения через pull request.** Почему важно: По активности решают, живой ли проект: заброшенную зависимость никто не обновит, когда в ней найдут ошибку. Сейчас: Pull request не используются. Что сделать: Вносите изменения через pull request даже в одиночку: история решений и место для проверок CI.

**5. Включите автообновление зависимостей.** Почему важно: Код без тестов, линтера и зафиксированных зависимостей дорого менять: ошибки находят пользователи, а не проверки.
