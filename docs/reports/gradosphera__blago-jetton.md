Порядок — по приросту балла на единицу усилий.

**1. Зафиксируйте версии зависимостей.** Почему важно: Код без тестов, линтера и зафиксированных зависимостей дорого менять: ошибки находят пользователи, а не проверки. Сейчас: Lock-файла нет. Что сделать: Закоммитьте package-lock.json (или pnpm-lock.yaml) и ставьте зависимости через npm ci.

**2. Выпустите релиз и поставьте тег версии.** Почему важно: По активности решают, живой ли проект: заброшенную зависимость никто не обновит, когда в ней найдут ошибку. Сейчас: Релизов и тегов нет. Что сделать: Поставьте тег версии (например, v1.0.0) и опубликуйте релиз с описанием изменений — и заведите CHANGELOG.

**3. Настройте CI.** Почему важно: Без автоматических проверок сломанная сборка и упавшие тесты попадают в основную ветку незамеченными. Сейчас: Конфига CI нет. Что сделать: Создайте .sourcecraft/ci.yaml: запуск на push и pull_request, шаги — npm ci, npm run lint, npm test. Pulse может подготовить этот файл в pull request.

**4. Подключите линтер.** Почему важно: Код без тестов, линтера и зафиксированных зависимостей дорого менять: ошибки находят пользователи, а не проверки. Сейчас: Конфиг линтера не найден. Что сделать: Настройте ESLint (eslint.config.js) или Biome (biome.json) и скрипт "lint" в package.json. Сначала включите рекомендуемый набор правил и исправьте найденное, потом добавьте запуск в CI.

**5. Проводите изменения через pull request.** Почему важно: По активности решают, живой ли проект: заброшенную зависимость никто не обновит, когда в ней найдут ошибку. Сейчас: Pull request не используются. Что сделать: Вносите изменения через pull request даже в одиночку: история решений и место для проверок CI.

**6. Добавьте .editorconfig.** Почему важно: Код без тестов, линтера и зафиксированных зависимостей дорого менять: ошибки находят пользователи, а не проверки. Сейчас: .editorconfig отсутствует. Что сделать: Положите .editorconfig в корень: кодировка utf-8, перевод строки lf, отступы как в проекте.

**7. Включите автообновление зависимостей.** Почему важно: Код без тестов, линтера и зафиксированных зависимостей дорого менять: ошибки находят пользователи, а не проверки.
