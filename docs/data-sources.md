# Источники данных, внешние сервисы и ИИ

## 1. SourceCraft REST API

Базовый адрес — `https://api.sourcecraft.tech`. Клиент — `src/lib/sourcecraft/client.ts`.
Типы генерируются из OpenAPI-спецификации платформы (`src/lib/sourcecraft/openapi/`,
команда `pnpm gen:api`).

Аутентификация:

- для публичных данных — сервисный персональный токен `SOURCECRAFT_PAT`;
- для приватных репозиториев и данных, доступных только участникам, — личный токен
  владельца. Он хранится зашифрованным (AES-256-GCM) и удаляется кнопкой «Отключить».

| Эндпоинт | Для чего используется |
|---|---|
| `GET /repos` | полный публичный каталог: лайки, дата активности, признаки форка, зеркала, шаблона, пустого репозитория |
| `GET /repos/{org}/{repo}` | карточка: язык, описание, видимость, ветка по умолчанию, адрес клона, счётчики |
| `GET /repos/{org}/{repo}/trees` | дерево файлов: наличие README, LICENSE, CI, тестов, линтера и других файлов (до 5000 записей) |
| `GET /repos/{org}/{repo}/branches` | ветки: верхушка ветки по умолчанию, ветки для дерева коммитов |
| `GET /repos/{org}/{repo}/tags`, `/releases`, `/releases/latest` | релизы и теги |
| `GET /repos/{org}/{repo}/contributors` | участники (до 200) |
| `GET /repos/{org}/{repo}/pulls` | выборка pull request (50 последних) |
| `GET /repos/{org}/{repo}/pulls/{slug}/comments` | комментарии 20 последних pull request для аналитики ревью (вне балла) |
| `GET /repos/{org}/{repo}/issues` | выборка задач (50 последних): статус, даты создания, начала работы, закрытия, изменения |
| `GET /repos/{org}/{repo}/cicd/runs` | прогоны CI (только с токеном участника) |
| `GET /user`, `GET /me/repos`, `GET /orgs/{org}/repos` | репозитории владельца токена |
| `GET /repos/{org}/{repo}/roles` | роль владельца токена в репозитории (admin или maintainer) |
| `POST /repos/{org}/{repo}/pulls` | создание pull request с правками от имени владельца |

Ограничение частоты: не чаще 8 запросов в секунду при лимите платформы 10. Одновременных
запросов не больше 4. На ответы 429 и 5xx — до трёх попыток с экспоненциальной задержкой.
Таймаут запроса — 20 с. Ответы проходят валидацию.

## 2. Git-репозиторий

API SourceCraft не отдаёт содержимое файлов и историю коммитов. Эти данные берутся из
git-клона.

| Параметр | Значение |
|---|---|
| Библиотека | isomorphic-git: чистый JavaScript, работает в serverless-среде без системного git |
| Что клонируется | одна ветка по умолчанию, без рабочей копии (`noCheckout`) |
| История | окно 90 дней, не глубже 2000 коммитов. Для репозиториев от 5000 записей в дереве — только верхушка |
| Время | попытка — до 90 с, всего — до 150 с. Вторая попытка берёт только верхушку |
| Чтение файлов | до 1500 файлов исходников по кругу из всех каталогов; файлы больше 200 КБ пропускаются |
| Пустые коммиты | дерево каждого коммита сравнивается с деревом родителя по уже скачанному логу, без дополнительных запросов |
| Хранение | временный каталог в `/tmp`, удаляется сразу после анализа |

Проверка новых коммитов выполняется без клона: один запрос `listServerRefs` к git-серверу
возвращает верхушку ветки по умолчанию.

## 3. SourceCraft AppSec

Базовый адрес — `https://appsec.sourcecraft.tech` (`APPSEC_API_URL`). Клиент —
`src/lib/security/sourcecraft-appsec.ts`.

| Эндпоинт | Для чего |
|---|---|
| `GET /v1/scans/latest?gitRepo=<uuid>` | последний скан репозитория |
| `GET /v1/defect-groups` | открытые находки SAST, SCA и secret scanning с критичностью |

AppSec отдаёт результаты только участникам репозитория, поэтому запросы выполняются
личным токеном владельца. Это единственный источник категории «Безопасность» и штрафов за
секреты и critical-уязвимости.

## 4. OSV.dev (справка, в балл не входит)

`https://api.osv.dev/v1/querybatch` и `/v1/vulns/{id}`. На вход — пакеты и версии из
`package-lock.json` и `pnpm-lock.yaml` публичного репозитория. Результат показывается на
странице анализа с пометкой «не SourceCraft AppSec, на балл не влияет». Для приватных
репозиториев OSV не вызывается.

## 5. Искусственный интеллект

Модель вызывается через OpenAI-совместимый роутер RouterAI (`AI_BASE_URL`, `AI_API_KEY`,
`AI_MODEL`). Модель по умолчанию указана в `.env.example`, администратор может сменить её в
админке. Провайдер — `src/lib/ai/router.ts`, раннер задач — `src/lib/ai/runner.ts`.

| Задача | Что получает модель | Как используется |
|---|---|---|
| `repo_kind` | README, перепись каталогов, вывод эвристики | проект или «полезный материал»; описание проекта |
| `file_selection` | только пути файлов (до 400) | какие файлы прочитать для ревью |
| `code_review` | фрагменты до 12 файлов по 4000 символов, измеренные метрики | балл категории «Код» и список находок |
| `readme_rubric` | README (до 6000 символов), до 80 путей | балл категории «Документация» |
| `pr_issues_digest` | выборка заголовков и статусов PR и задач | сводка; в балл не входит |
| `recommendation_copy` | готовые рекомендации без текстов репозитория | справочный вариант формулировок; на странице не используется |
| `improve_docs`, `improve_code` | README и файлы ревью (только по запросу владельца) | правки для pull request |

Правила работы с моделью:

- **Проверяемость.** Ответ проходит проверку схемы Zod. Невалидный ответ повторяется один
  раз, затем задача считается неудавшейся, и движок использует детерминированные метрики.
- **Воспроизводимость.** Ответы кэшируются в таблице `ai_cache` по SHA-256 от задачи и входа.
  Повторный анализ неизменённых файлов получает тот же ответ.
- **Бюджет.** Каждый вызов записывается в `ai_calls` с токенами и стоимостью из
  `usage.cost` роутера. При превышении месячного бюджета (`AI_MONTHLY_BUDGET_RUB` или
  настройка в админке) вызовы прекращаются, анализ продолжается без модели.
- **Конфиденциальность.** Код приватных репозиториев в модель не отправляется.
- **Границы влияния.** Модель определяет баллы только двух категорий — «Код» и
  «Документация» — и только когда ответ получен. Безопасность, активность, CI/CD, задачи,
  штрафы и рекомендации модель не затрагивает.

## 8. Хранение и лицензии

- Исходный код репозиториев не хранится. Клон живёт только во время анализа.
- В фактах анализа сохраняются производные данные: счётчики, пути, флаги, README,
  фрагменты выборки ревью публичных репозиториев. Они нужны, чтобы показать основания оценки.
- Фрагменты кода открытых репозиториев передаются во внешнюю модель только для анализа и не
  публикуются.
- Личные токены SourceCraft хранятся зашифрованными ключом `TOKEN_ENCRYPTION_KEY`
  (или ключом, выведенным из `AUTH_SECRET`).
