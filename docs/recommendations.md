# Алгоритм формирования рекомендаций

Рекомендации строит движок оценки (`src/lib/scoring/recommendations.ts`) по тем же метрикам,
из которых складывается Repo Health Score. Алгоритм детерминирован: одинаковые факты дают
одинаковый список в одинаковом порядке. Текст рекомендаций модель не пишет и не меняет.

## 1. Состав рекомендации

| Поле | Содержание | Источник |
|---|---|---|
| Проблема | Заголовок шага, например «Добавьте автотесты» | справочник заголовков по виду рекомендации |
| Факты | Текущее измеренное значение, например «3 файла тестов на 120 файлов кода» | расшифровка метрики |
| Почему важно | Последствия проблемы для проекта | справочник по категории (`src/lib/scoring/insights.ts`) |
| Действие | Конкретные шаги с учётом стека проекта: инструмент тестов, линтер, формат манифеста | `src/lib/scoring/how-to.ts`, стек определяется по файлам репозитория |
| Приоритет | Высокий, средний или низкий | раздел 4 |
| Трудозатраты | Тривиально, мало, средне, много | свойство метрики |
| Влияние на балл | Ожидаемый прирост Repo Health Score | моделирование, раздел 3 |
| Категория | Какую категорию затрагивает шаг | свойство метрики |

## 2. Кандидаты

Кандидат — метрика, которая одновременно:

- имеет данные (не «нет данных»);
- ниже своей цели (цели перечислены в [methodology.md](methodology.md), раздел 3);
- имеет вид рекомендации и оценку трудозатрат.

Метрики без данных рекомендаций не порождают: нельзя советовать исправить то, что не
измерено. Оценки модели (`code.ai_review`, `docs.ai_rubric`) тоже не порождают рекомендаций.
Конкретные замечания модели показываются отдельным списком находок.

## 3. Выбор шагов

Шаги выбираются жадно, по одному:

```
текущие_метрики ← метрики анализа
текущий_балл    ← Repo Health Score
выбранные       ← ∅

пока |выбранные| < 12:
    для каждого кандидата c ∉ выбранные:
        метрики' ← текущие_метрики, где c поднят до своей цели
        штрафы'  ← штрафы без тех, что снимаются выбранными шагами и c
        балл'    ← формула Repo Health Score (methodology.md, раздел 4) на метрики' и штрафы'
        прирост  ← балл' − текущий_балл
        если прирост > 0: ценность ← прирост / трудозатраты(c)
    если подходящих кандидатов нет: стоп
    взять кандидата с наибольшей ценностью
    текущие_метрики ← метрики' этого кандидата
    текущий_балл    ← текущий_балл + его прирост
    добавить его в выбранные
```

Трудозатраты в условных единицах:

| Уровень | Единиц | Примеры |
|---|---:|---|
| `trivial` | 1 | добавить LICENSE, `.gitignore`, описание репозитория |
| `small` | 3 | CHANGELOG, линтер, шаги CI |
| `medium` | 8 | тесты, настройка CI, закрытие уязвимостей |
| `large` | 20 | разбиение длинных файлов, снижение зависимости от одного автора |

Связь рекомендаций и штрафов:

| Рекомендация по метрике | Снимает штраф |
|---|---|
| `docs.license` | `missing_license` (−8) |
| `security.critical_vulns` | `critical_vuln_unfixed` (−10) |
| `security.secrets` | `secret_in_code` (−15) |

Поэтому прирост от добавления LICENSE включает и снятие штрафа.

**Следствие последовательного счёта.** Каждый прирост считается от состояния, в котором
предыдущие шаги уже выполнены. Сумма приростов всех шагов равна итоговому росту балла, и
обещанный результат не превышает 100. Второй шаг в той же категории приносит меньше первого:
категории нормируются.

## 4. Приоритет

| Условие | Приоритет |
|---|---|
| Рекомендация из категории «Безопасность» (находка AppSec) | высокий |
| Прирост ≥ 5 баллов | высокий |
| Прирост ≥ 2 баллов | средний |
| Остальные | низкий |

Находки безопасности всегда получают высокий приоритет, даже при небольшом приросте балла:
это прямой риск эксплуатации, а не гигиена.

## 5. Пример

Репозиторий: 58 баллов, штрафов нет, AppSec недоступен.

| № | Рекомендация | Факты | Приоритет | Прирост |
|---:|---|---|---|---:|
| 1 | Настройте CI | Конфига CI нет | высокий | +8,1 |
| 2 | Заполните описание репозитория | Описание пустое | низкий | +1,4 |
| 3 | Добавьте автотесты | 2 файла тестов на 64 файла кода | средний | +3,2 |

Числа в примере иллюстративные. Реальные значения для конкретного репозитория — в его
отчёте на стенде и в выгрузке.

## 6. Где показываются

- Страница анализа `/a/<id>`, блок «Рекомендации».
- Markdown-отчёт `/a/<id>/report.md` и PDF-отчёт `/a/<id>/export/report.pdf`.
- Публичный API `GET /api/public/repos/<org>/<repo>/report`.

Для владельца репозитория рекомендации по документации и коду можно превратить в
pull request с правками: см. [star-features.md](star-features.md).
