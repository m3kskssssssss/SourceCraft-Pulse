# Функции со звёздочкой

Соответствие пяти направлениям раздела 7 технического задания. В столбце «Статус»:
«реализовано» — функция работает сквозным сценарием на данных SourceCraft, «частично» —
реализована часть возможностей направления, «нет» — не реализовано.

## 1. Рейтинг и сравнение

| Возможность ТЗ | Статус | Реализация |
|---|---|---|
| История изменения Repo Health Score | реализовано | блок «История оценок» на карточке репозитория `/r/<org>/<repo>` и под шапкой страницы анализа: график, все запуски с изменением балла, отметки плановых проверок «новых коммитов нет — оценка та же» и переоценок после новых коммитов |
| Объяснение позиции | реализовано | в строке рейтинга — баллы шести категорий: сначала категории с данными, затем «нет данных» и нули в приглушённом виде. На странице анализа — сильные и слабые стороны, покрытие данных, причина исключения из рейтинга |
| Сводка рейтинга | реализовано | `/rating`: число репозиториев, средний балл и медиана, распределение баллов, средние по категориям, языки |
| Дополнительные фильтры и сортировки | частично | фильтр по языку, поиск по имени; сортировки по баллу, лайкам, последней активности, отзывам. Фильтров по тематике, размеру, наличию CI и статусу безопасности нет |
| Динамика позиции в leaderboard | нет | |
| Сравнение репозиториев | нет | |

|---|---|---|

| Аналитика issues с длительностью обработки | реализовано | медиана дней от создания задачи до начала работы или закрытия, доля зависших задач, доля закрытых |
| Путь развития репозитория | реализовано | интерактивное дерево коммитов с ветвлениями и слияниями на странице анализа |
| Анализ review-комментариев и bottlenecks | нет | |
| Карта владельцев файлов | нет | |

## 3. Публичность результата

| Возможность ТЗ | Статус | Реализация |
|---|---|---|
| Публичные quality badges | реализовано | `GET /api/badge/<org>/<repo>.svg` — бейдж с баллом; `GET /api/card/<org>/<repo>.svg` — карточка с категориями |

## 4. AI-возможности

Модель не подменяет фактическую аналитику. Её ответы проходят проверку схемы, кэшируются и
влияют на балл только двух категорий — «Код» и «Документация» ([data-sources.md](data-sources.md),
раздел 5).

| Возможность ТЗ | Статус | Реализация |
|---|---|---|
| AI-summary состояния проекта | реализовано | блок «Что это · О проекте» на странице анализа и в отчёте: назначение репозитория и темы |
| AI-оценка кода и документации | реализовано | ревью выборки исходников по пяти критериям с конкретными находками рядом с измеренными числами; рубрика README по пяти критериям |
| AI-рекомендации, подтверждённые фактами | реализовано | для подтверждённого владельца — подготовка pull request с правками документации и кода: модель предлагает правки, каждая правка применяется только если исходный фрагмент найден в файле ровно один раз. Превью с диффом, выбор правок галочками, ожидаемый прирост балла. Pull request создаётся в SourceCraft от имени владельца. Код приватных репозиториев в модель не передаётся: для них предлагаются только шаблоны файлов |

## 5. Защита публичного рейтинга

| Возможность ТЗ | Статус | Реализация |
|---|---|---|
| Защита от копий | реализовано | форки, зеркала, шаблоны и копии шаблонов с историей из одного-двух коммитов получают балл, но не место в рейтинге. Причина показывается на странице анализа |
| Защита от накрутки лайков | реализовано | лайки не входят в балл, сортировка по умолчанию — по баллу |
| Защита от пустых коммитов и искусственной активности | частично | коммиты и авторы учитываются по логарифмической шкале с потолком (50 коммитов, 5 авторов за 90 дней). Вес активности — 15 %. Пустые коммиты отдельно не распознаются |
| Защита от массовых запусков | реализовано | лимиты анализов на пользователя (10 в сутки, 3 одновременно), лимиты частоты публичного API |
